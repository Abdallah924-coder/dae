# DAE Crypto

Plateforme d’achat et de vente de cryptomonnaies avec API Express, MongoDB et interface React.

## Développement

Utilisez Node.js 20 ou plus récent, puis installez les dépendances avec `npm ci`.

- `npm run dev` démarre l’API Express sur le port 3000 avec redémarrage automatique.
- `npm run dev:client` démarre Vite sur le port 5173. La configuration Vite relaie `/api` et `/images` vers Express.
- `npm run build` compile l’interface React dans `public/app`.
- `npm start` démarre l’API. Compilez d’abord l’interface si le dossier `public/app` n’existe pas.

L’API a besoin de `MONGODB_URI`. Les notifications e-mail, SMS et la connexion d’administration utilisent les variables documentées dans `.env.example`.

## Déploiement Render

Render installe les dépendances, compile React avec `npm run build`, puis démarre Express. Le serveur sert les routes publiques `/`, `/acheter`, `/vendre`, `/suivi`, `/attente`, `/contact` et `/admin`, ainsi que les routes de compte `/inscription`, `/connexion`, `/mot-de-passe-oublie`, `/compte`, `/portefeuille`, `/depot`, `/retrait`, `/staking`, `/verification` et `/securite` depuis l’application React. Les endpoints métier restent sous `/api`.

Le taux par défaut est de **635 FCFA/USDT quand le client achète** et **580 FCFA/USDT quand il vend**. Au démarrage, si le dernier taux USDT enregistré vaut encore 570 FCFA à la vente, l’application ajoute un nouveau taux à 580 en conservant l’ancien dans l’historique. Les autres taux enregistrés restent prioritaires et modifiables dans Administration → Taux & limites. Le parcours achat/vente obtient sa cotation par l’API DAE, qui calcule les montants en unités entières (8 décimales crypto, prix source à 12 décimales), arrondit le FCFA au franc selon le sens, puis signe une cotation valable cinq minutes. La commande conserve cette cotation et stocke les quantités crypto en Decimal128; une précision d’entrée supérieure à 8 décimales est refusée.

La création des commandes, leurs changements de statut et leurs événements d’audit sont validés ensemble dans une transaction MongoDB. Utilisez un replica set ou une topologie MongoDB compatible avec les transactions multi-documents. Le script `npm run expire` traite en une fois les commandes échues; planifiez son exécution régulière dans l’environnement de déploiement.

La création d’ordre est idempotente par compte : une reprise réseau avec la même clé UUID et les mêmes détails retourne la commande existante, même si la cotation a expiré; une réutilisation de la clé avec des détails différents renvoie vers la commande déjà enregistrée. Après un rechargement de page, l’interface recherche cette commande avant de proposer un nouvel envoi.

Le tableau de marché affiche 14 cryptos de référence; les liens d’achat et de vente ne sont actifs que pour les cinq actifs déjà pris en charge par le parcours d’ordre. Le graphique utilise l’API CoinGecko sur une journée et regroupe les observations récentes par heure. Il s’agit d’un repère indicatif, pas d’un carnet d’ordres DAE ni du taux contractuel FCFA de l’écran d’achat/vente. La granularité automatique et l’endpoint `market_chart` sont décrits dans la [documentation CoinGecko](https://docs.coingecko.com/reference/coins-id-market-chart). Les données horaires historiques CoinPaprika utilisées auparavant nécessitent une offre payante au-delà de la période gratuite, comme l’illustre la [documentation CoinPaprika](https://docs.coinpaprika.com/api-reference/tickers/get-historical-ticks-for-a-specific-coin).

Binance Pay est proposé comme transfert manuel, sans connexion à l’API Binance. Configurez le Binance UID de DAE dans Administration → Configuration. À l’achat, le client peut donner son UID pour recevoir les cryptos ; à la vente, il envoie les cryptos vers l’UID DAE affiché. Le paiement ou le versement en FCFA reste effectué par Mobile Money.

## Comptes clients et conservation

Les routes `/inscription`, `/connexion`, `/mot-de-passe-oublie`, `/compte`, `/portefeuille`, `/depot`, `/retrait`, `/staking`, `/verification` et `/securite` forment l’espace client. La page Sécurité liste les sessions actives et permet de révoquer les autres appareils. La watchlist des marchés se synchronise avec le compte. Pour ouvrir l’inscription, configurez les fournisseurs e-mail/SMS, `CUSTOMER_AUTH_SECRET` (au moins 32 caractères aléatoires), `CUSTOMER_LEGAL_REVIEWED=true` et `PUBLIC_APP_URL=https://dae-1lpj.onrender.com`. Les variables `CUSTOMER_TERMS_VERSION`, `CUSTOMER_PRIVACY_VERSION`, `CUSTOMER_TERMS_URL` et `CUSTOMER_PRIVACY_URL` sont facultatives; le formulaire peut afficher les liens lorsqu’ils seront publiés. Cette validation d’environnement est une attestation opérateur, pas un avis juridique. Les suspensions/réactivations admin et la récupération du mot de passe révoquent les sessions dans la même transaction que le changement d’état; configurez MongoDB en replica set, cluster shardé ou topologie Load Balanced compatible. La préparation affiche si cette capacité est détectée. Les actions admin et motifs sont conservés dans un journal append-only. Les statuts KYC sont modifiables par revue manuelle depuis l’administration.

La création d’un ordre d’achat ou de vente exige un compte actif avec e-mail et téléphone vérifiés; l’ouverture de session est protégée par un code envoyé sur chacun des deux canaux. Le mode invité ne peut pas créer d’ordre.

DAE opère en République du Congo et conserve les actifs de ses clients. Pour BSC, l’application dérive les adresses de dépôt depuis le xpub, indexe le jeton Binance-Peg BSC-USD, crédite le grand livre après confirmations et approbation KYC, réserve les soldes avant retrait et transmet les transactions au signataire. Les workers sont exécutés par DAE sur sa propre machine avec `npm run bsc:deposits` et `npm run bsc:signer`; ils doivent utiliser le même `MONGODB_URI` de production que le site Render. Le signataire dérive les clés clientes, maître et gaz depuis `BSC_SIGNER_MNEMONIC`, conservée dans `.env.signer` sur cette machine. Ne mettez jamais cette phrase dans Git, Render, l’API ou MongoDB. Le journal de reprise peut conserver une transaction signée chiffrée dans MongoDB, avec une clé dérivée de cette phrase. Cette architecture n’est pas un HSM/MPC ni un audit indépendant.

Les workers locaux lisent la configuration commune dans `.env`; le signataire lit aussi `.env.signer` pour la phrase secrète. Ces deux fichiers sont ignorés par Git. La base locale de développement utilise `mongodb://127.0.0.1:27018/usdt_cfa?replicaSet=rs0`, avec ses fichiers dans `.local-mongo/`. Elle est isolée de la base de production Render : les écritures locales ne sont pas visibles sur le site en ligne. Pour que les workers locaux traitent les opérations du site en production, il faut remplacer `MONGODB_URI` par l’URI externe de la base de production et autoriser l’adresse IP de la machine si nécessaire. Pour l’indexeur local, `BSC_DEPOSITS_ENABLED=true` est requis dans `.env`. Lancez `npm run bsc:deposits` dans un terminal et `npm run bsc:signer` dans un autre; laissez la machine allumée et les commandes actives, sinon les heartbeats expirent. Les dépôts et retraits restent désactivés dans le service web jusqu’à activation explicite de `BSC_DEPOSITS_ENABLED` et `BSC_WITHDRAWALS_ENABLED` dans Render. Avant tout mouvement réel, vérifier le xpub, le bloc de départ, les adresses maître/gaz, la phrase du signataire, le financement BNB du portefeuille gaz, les transactions MongoDB et les heartbeats. Staking reste désactivé. `DAE_REGULATORY_REVIEWED` est une attestation de configuration, pas une autorisation vérifiée par l’application. Voir [docs/CUSTODY_ARCHITECTURE.md](docs/CUSTODY_ARCHITECTURE.md) pour les contrôles opérationnels.
